# product/features/

Une spec par fonctionnalité.

## Ce qu'on met ici

`<nom-de-la-feature>.md`, en kebab-case. Chaque spec contient : le problème utilisateur, le comportement attendu, ce qui est explicitement hors périmètre, les cas limites, et comment on saura que ça marche.

## Ce qu'on ne met pas ici

- Des idées de fonctionnalités pas encore décidées → `brainstorm/ideas.md`.
- Du code.

## Règle

Une spec dit ce que le produit fait, pas comment il est codé. Si la spec ne définit pas ce qui est hors périmètre, elle n'est pas finie.
