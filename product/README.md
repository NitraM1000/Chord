# product/

Ce qu'on construit, dans quel ordre, et comment on vérifie qu'on a raison.

## Ce qu'on met ici

- `roadmap.md` — les grandes étapes et leur ordre.
- `user-stories.md` — les besoins exprimés du point de vue de l'utilisateur.
- `experiment-board.md` — le cœur de la démarche : hypothèse → test → résultat → décision.
- `features/` — une spec par fonctionnalité.

## Ce qu'on ne met pas ici

- Les idées non retenues → `brainstorm/`.
- Le modèle économique et le prix → `business/`.
- Les données d'entretien qui justifient une story → `research/`, avec un lien depuis la story.

## Règle

Une fonctionnalité qui n'est reliée à aucune hypothèse de l'experiment board ni à aucun signal de `research/` est une fonctionnalité qu'on construit parce qu'elle nous plaît. C'est autorisé, mais ça doit être dit.
