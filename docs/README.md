# docs/

La documentation de référence du projet. C'est ici qu'on écrit ce qui est **stabilisé**.

## Ce qu'on met ici

- `vision.md` — le problème, pour qui, pourquoi maintenant.
- `positioning.md` — proposition de valeur et différenciation.
- `glossary.md` — le vocabulaire interne, pour qu'on parle tous la même langue.
- `faq.md` — les questions qui reviennent, avec des réponses courtes.
- `decisions/` — une décision structurante = un fichier daté et numéroté.

## Ce qu'on ne met pas ici

- Des idées non validées → `brainstorm/ideas.md`.
- Des notes d'entretien ou de la recherche brute → `research/`.
- Des specs de fonctionnalités → `product/features/`.
- Des chiffres business → `business/`.

## Règle

Un document de `docs/` est censé être vrai au moment où on le lit. S'il ne l'est plus, on le corrige — on ne laisse pas deux versions coexister.
